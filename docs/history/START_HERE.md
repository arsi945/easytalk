# easytalk: перенос на другой Mac / Xcode

Только текущие версии: **iOS 0.5.0 / build26**, **macOS 0.4.1 / build11**. Этот комплект предназначен для установки через Xcode и дальнейшей разработки. Исходники приложения совпадают с текущей рабочей версией; меняются лишь пути ресурсов/SwiftPM и настройки подписи копии проекта.

## iPhone: открыть и установить

1. Распаковать весь ZIP в обычную папку на Mac. Не открывать проект непосредственно внутри ZIP и не переносить только файл `.xcodeproj`.
2. Открыть **`ios/EasyTalk.xcodeproj`**. Выбрать схему **EasyTalk**.
3. В Xcode → Settings → Accounts добавить свой Apple Account. В проекте → TARGETS → Signing & Capabilities выбрать свою **Team для всех трёх targets**: EasyTalk, EasyTalkKeyboard, EasyTalkVoiceActivity. Automatic Signing включён. Третий target сохранён из текущей сборки, но не используется для запуска диктовки.
4. Подключить разблокированный iPhone, подтвердить доверие/Developer Mode, если iOS запросит. Выбрать iPhone как устройство запуска и нажать **▶ Run**.
5. На iPhone: Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры → easytalk. Включить полный доступ для обращения к текстовому AI API. Включение диктовки также находится в системных настройках клавиатуры.
6. В настройках самого easytalk указать свой API-ключ. В обычном поле Заметок/Telegram выбрать easytalk через 🌐. Для диктовки используется нижний системный 🎙 iOS; подготовка микрофона в приложении не нужна.

На этом компьютере проект проверялся **Xcode16.2 / SDK18.2**, телефон — iPhone12ProMax/iOS27. Системный Xcode на другом Mac не обязан лежать в прежней папке Downloads. Если новый Xcode просит установить iOS Platform Support — установить предложенный компонент. Возможность сборки с конкретной другой версией Xcode проверяется на ней, не гарантируется по одному номеру iOS.

Личная Team, сертификаты, provisioning profiles, API-ключи, словарь пользователя и контейнеры приложений не передаются. Team выбирается на новом компьютере. Для обновления существующего приложения сохранять прежние bundle IDs и аккаунт подписи, не удалять приложение ради переустановки. Если разработчик использует другой аккаунт и Apple не позволяет зарегистрировать прежние IDs, потребуется собственный согласованный префикс для всех трёх targets; это уже отдельная установка с отдельными данными.

## Зависимости уже внутри комплекта

- **Веса модели исключены по прямой просьбе автора.** `Resources/LocalVoice/model` содержит только описание. Статус, причина отказа и код для будущего исследования — `docs/LOCAL_MODEL_STATUS.md` / `local_voice/model_manifest.json`.
- `Vendor/onnxruntime`: официальный ONNX Runtime1.19.2, исходники Objective-C bindings, iPhone arm64 и симулятор arm64/x86_64. Локальный Swift package, без загрузки пакета с GitHub при первой iOS-сборке. Неиспользуемые Extensions/training и Mac slice не включены. Происхождение/лицензия — рядом.
- Промпты, идиомы и generated Swift уже подготовлены. Python не нужен для обычного открытия/Run в Xcode. Для изменения промптов: `python3 ios/generate_project.py`. Для изменения каталога: `python3 scripts/generate_idioms.py`.

Локальная модель относится к отдельной экспериментальной лаборатории произношения и в комплект не включена. ONNX Runtime оставлен только как зависимость компиляции существующего прототипа; это библиотека, не веса модели. Рабочая диктовка26 — системная iOS, не эта модель. Распознавание на лету подтверждено пользователем. Русские вставки внутри английской диктовки пока распознаются неверно; смешанный EN+RU голосовой ввод не решён. Перевод/грамматический разбор требуют доступа к выбранному API и собственный ключ.

## Mac: разработка и сборка

Для просмотра в Xcode открыть корневой **Package.swift**. Для сборки обычного `.app` с Info.plist, Services и ресурсами из корня комплекта:

```sh
bash scripts/build.sh all
build/selftest
open build/easytalk.app
```

Сборка создаётся для архитектуры текущего Mac. Сначала проверить `xcrun --find swiftc`: должен находиться компилятор установленного Xcode. При необходимости использовать `DEVELOPER_DIR` с реальным путём Xcode этого компьютера; системные CLT/xcode-select ради обычной сборки не менять. Для установки перенести готовый `build/easytalk.app` в Applications. Полный Accessibility доступ нужен только для внешней вставки; основной перевод/копирование доступны отдельно.

Основное Mac-приложение не требует Python. Его необязательная лаборатория произношения использует Python3.12 и numpy/onnxruntime/cmudict. Перенос чужого Intel venv на другой Mac некорректен, поэтому venv/колёса старого компьютера не включены. По просьбе автора веса не включены; подготовка только Python не включит лабораторию. Будущее восстановление модели/среды описано в docs/LOCAL_MODEL_STATUS.md. Для обычной Mac-сборки это не требуется. Опциональная подготовка окружения:

```sh
python3.12 -m venv build/local-voice/venv
build/local-voice/venv/bin/python -m pip install -r local_voice/requirements.txt
bash scripts/build.sh app
```

Эта установка зависимостей требует сети; модель после неё всё ещё нужно отдельно восстановить по LOCAL_MODEL_STATUS.md. Лаборатория отложена по просьбе автора; она не влияет на перевод/словарь/карточки или системную iOS-диктовку. Mac build script записывает пути этого компьютера и ожидает опциональную модель в Resources, но не загружает её.

## Для следующего разработчика

Сначала **docs/HANDOFF.md**, затем **docs/ARCHITECTURE.md**, **AGENTS.md**. Действующее iOS-решение — SYSTEM_DICTATION_026.md; Mac — MACOS_041.md. Concept/CHANGELOG/другие Markdown сохранены как объяснение решений. Исторические упоминания прежних source archives, build paths, evidence, скриншотов или неактивных voice-return файлов не означают их наличие в этом компактном комплекте. Верхние актуальные разделы имеют приоритет.

Не возвращать app hop, подготовку микрофона каждые5минут, промежуточный transcript/Insert. Не отправлять пользовательские фразы/голос в AI для диагностики без актуального разрешения и не читать Keychain ради диагностики. Ключи вводятся пользователем в приложении на новом компьютере/телефоне.

Проверки из корня: `bash scripts/test_ios_core.sh`, `bash scripts/build.sh all`, `build/selftest`, `build/easytalk.app/Contents/MacOS/easytalk --desktop-check build/desktop-check`. Для iOS: обычный Simulator/Device build в Xcode. Компиляция не доказывает живую работу внешней вставки, AI или качество клавиатуры.

`TRANSFER_MANIFEST.json` содержит размеры/SHA256 всех передаваемых файлов. Контрольная сумма ZIP — отдельный файл рядом. Полная исходная папка не удаляется и не очищается этим упаковщиком.
