# Экспериментальная локальная модель: не входит в отправляемый комплект

8 октября2026 автор прямо попросил **не передавать веса модели**: локальная оценка речи не принята как работающая функция. В компактном комплекте сохранены объяснение, код прототипа, manifest/лицензии и инструкции для будущего разработчика. Нет `model.int8.onnx`, Python venv, wheels или записей голоса. Обычный Xcode-проект должен собираться без весов; папка Resources/LocalVoice/model содержит только этот документ.

## Что это за модель

Это **акустическая ONNX-модель распознавания фонем**, не текстовая LLM и не используемый переводчиком AI. Основа: `asingingbird/buddy-pronunciation-onnx`, revision `bbc37113ff91fdda6b2b1a79f44fbb78bdc4c588`; source model `nrshoudi/speech_ocean_wav2vec_mdd`, Apache2.0. INT8 ONNX весит примерно340MiB. Точный файл/SHA256 и источники — local_voice/model_manifest.json.

Вход прототипа: короткая **заранее известная английская фраза** и WAV mono16кГц; выход — предполагаемые фонемы и сопоставление с CMUdict. Это не полноценный преподаватель произношения, не универсальная диктовка и не надёжный балл/100. В нём нет проверенной оценки ударения/интонации/беглости.

## Почему отложили

- На синтетических системных голосах технический inference работал. Это не подтверждает качество обратной связи для живого русскоязычного ученика.
- В прототипе встречались спорные замечания даже к синтетическому произношению. Нет независимой оценки на человеческом корпусе, калибровки допустимых акцентов/редукции, false-positive статистики. Выдавать результат за готовую проверку произношения нельзя.
- Размер/память/батарея на iPhone нуждаются в отдельном измерении и оптимизации. Модель не следует загружать в keyboard extension.
- Проблемы прежнего микрофонного обхода были **отдельной архитектурной проблемой iOS**: custom keyboard не получает прямой захват audio. Запуск recorder через основное приложение приводил к переходам/подтверждениям/preview. Автор отверг такой UX; наличие ONNX-модели это ограничение не снимает.
- Рабочая диктовка build26 использует **системный микрофон iOS**, распознаёт текст на лету, и приложение не получает исходное audio для акустического анализа. EN+RU смешанная диктовка остаётся отдельной нерешённой задачей.

Пользователь попросил пока оставить обычное распознавание, без анализа произношения. Экспериментальные экраны/код не считаются готовой функцией. Без весов локальная лаборатория анализ выполнить не сможет; перевод, разбор грамматики, словарь, карточки и штатная диктовка работают независимо.

## Что сохранено и как продолжать

- iOS: `ios/EasyTalk/LocalAcousticModel.swift`, `LocalPronunciationController.swift`; Mac: `Sources/EasyTalk/LocalPronunciation.swift`.
- Общее сопоставление: `Sources/EasyTalkCore/PronunciationAlignment.swift`.
- Python-прототип/тесты/manifest: `local_voice/`. Более подробная история — docs/LOCAL_VOICE.md; старые пункты о5-минутной подготовке/голосовом мосте **устарели**, действующее решение — docs/SYSTEM_DICTATION_026.md.
- `Vendor/onnxruntime` в переносимом комплекте — официальная **библиотека исполнения1.19.2**, не модель. Она нужна для компиляции уже существующего LocalAcousticModel.swift, поэтому включена локально. В ней нет весов/пользовательского audio. При отдельном будущем рефакторинге лаборатории runtime тоже можно убрать; сейчас исходники рабочего приложения не переписываются ради упаковки.

Если решено вернуться к исследованию: взять модель из сохранённого исходного компьютера/архива либо явно загрузить по pinned manifest; проверить SHA, собрать человеческую проверочную выборку с разрешением и оценить ложные замечания до изменения UX. Ничего не загружается автоматически при запуске приложения или открытии проекта.

На переносимом Mac путь модели для лаборатории — `Resources/LocalVoice/model`; окружение создаётся заново в `build/local-voice/venv`. Восстановление опционально и требует Python3.12/сети, если исходных ресурсов рядом нет:

```sh
python3.12 -m venv build/local-voice/venv
build/local-voice/venv/bin/python -m pip install -r local_voice/requirements.txt
build/local-voice/venv/bin/python local_voice/setup_model.py --directory Resources/LocalVoice/model
bash scripts/build.sh app
```

Эти команды относятся только к будущему эксперименту. Для установки и основных функций приложения запускать их **не нужно**.
