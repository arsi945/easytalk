# JustTalk easy (easytalk) --- концепция ввода и перевода

## Реализация iPhone — решение автора от 2026-10-05

Обычный ввод — единственный режим клавиатуры. Панель: «Перевести», «Учёба», ⚙.
Отдельного черновика и переключателя «Тренировка» нет. Перевод сразу заменяет
доступный текст поля; материал для учёбы сохраняется независимо от отправки.
Первая версия открывает разбор и локальный словарь внутри клавиатуры, чтобы
не требовать App Groups и не уводить пользователя из сообщения. История
содержит до 30 разборов, словарь — до 200 записей с исходным и исправленным
контекстом. Синхронизации с основным приложением пока нет.

iOS: переводится выделение или доступный абзац перед курсором в конце абзаца.
Если курсор внутри текста, пользователь переносит его в конец либо выделяет
нужный фрагмент. API может ограничивать контекст: полный доступ ко всему полю
не гарантируется. Ответ не применяется после смены поля, текста или выделения.
Произвольные фразы без настроенного API-подключения не проверяются и не переводятся.

Уточнение автора: для личного iPhone используется прямое подключение к OpenAI API
с ключом в Keychain. Отдельный сервер не нужен. Предыдущая строка означает
реальное подключение по ключу; сервер остаётся необязательной альтернативой.

### Дополнение контракта AI Core: `analyze_translate`, schema_version 1

Запрос `POST /v1/ai`:

```json
{"op":"analyze_translate","schema_version":1,"text":"He want coffee", "native_language":"ru","target_language":"en","context":"casual_chat"}
```

Необязательное поле `speaker_gender`: `male` или `female` — выбранный пользователем
пол говорящего для перевода от первого лица («я сделал / сделала»). Если пол не
указан, поле отсутствует; AI опирается на текст и не придумывает пол. Явный род
в исходном сообщении имеет приоритет, пол других людей и цитат этим параметром
не меняется. Схема ответа остаётся 1. Настройка доступна в приложении и в ⚙
клавиатуры; из приложения передаётся вместе с подключением при ручном импорте.

Ответ содержит исправленный английский, естественный русский перевод и разбор:

```json
{"schema_version":1,"corrected":"He wants coffee","translated":"Он хочет кофе", "diffs":[{"id":"d1","type":"error","original":"want","corrected":"wants","start":3,"end":7,"explanation":"После he в Present Simple добавляем -s."}],"vocabulary":[]}
```

Смещения — Unicode code points исходного текста. Типы правок прежние:
error, unnatural, style, unknown_word. `explanation` — короткое объяснение
на русском. Vocabulary: `{term, meaning, kind}`; kind — word, phrase, idiom,
meaning — значение на русском, term встречается в исправленном английском.
Одна операция возвращает весь результат. Ошибочный/неполный ответ не должен
считаться грамотным текстом; при ошибке исходный текст остаётся в поле.
Старые операции correct и translate сохраняют свои контракты.

Уточнение реализации 2026-10-06 (iOS 0.3.3): соседние слова, пропущенные в границе
объяснённой правки, можно включить локально, если все предложенные замены находятся
в итоговом английском в том же порядке. Итоговые правки обязаны точно восстановить
corrected, не перекрываться и сохранять объяснения; несуществующие фрагменты,
противоречивые замены и переписывание без правок отклоняются. Неполные style-правки
локально не расширяются, чтобы не скрыть ошибку и не выдать незаслуженную награду.
Vocabulary — необязательные подсказки: неподходящий term пропускается, не блокируя
проверенный перевод. Прямой gpt-6-luna получает JSON Schema strict; форма контракта 1
не меняется. Остальные способы подключения сохраняют прежний формат запроса.

## 1. Основная идея

JustTalk easy не требует писать текст в отдельном окне приложения.

Пользователь работает в привычных приложениях: Telegram, WhatsApp,
Gmail, браузере, Slack, Discord, редакторах и других приложениях с
полями ввода.

JustTalk easy работает как языковой обучающий слой поверх обычной
коммуникации.

``` text
Пишешь там, где всегда писал
→ пытаешься выразить мысль на изучаемом языке
→ нажимаешь Translate
→ JustTalk easy получает текст
→ AI анализирует его
→ ошибки и неизвестные слова сохраняются
→ текст переводится на родной язык
→ исходный текст заменяется переводом
→ пользователь отправляет сообщение
```

## 2. Основной UX

В основном режиме у JustTalk easy нет собственного поля ввода.

Пример текста в Telegram:

``` text
I don't know what he want от меня
```

Пользователь нажимает `Translate`.

AI: 1. Понимает смысл. 2. Проверяет английский. 3. Находит ошибки. 4.
Находит вставки на родном языке. 5. Определяет правильный английский
вариант по контексту. 6. Сохраняет учебный материал. 7. Создаёт
естественный перевод на родной язык.

После обработки текст в исходном поле заменяется:

``` text
Я не знаю, чего он от меня хочет.
```

Пользователь отправляет сообщение обычным способом.

## 3. Главный принцип UX

Обучение не должно мешать коммуникации.

``` text
написал → Translate → получил родной текст → отправил
```

Разбор ошибок необязателен в момент написания. Учебный материал
сохраняется для последующего изучения.

## 4. Если текст написан правильно

Если существенных ошибок нет, показывается короткое положительное
уведомление:

``` text
✓ Всё правильно. Отлично!
```

После этого текст заменяется переводом на родной язык.

## 5. Если есть материал для изучения

Если AI обнаружил грамматические ошибки, неестественные конструкции,
неизвестные слова, полезные выражения или идиомы, перевод всё равно
выполняется сразу.

Кнопка `Учёба` рядом с настройками начинает мягко подсвечиваться или
пульсировать оранжевым.

Она означает: в последних сообщениях есть материал для разбора.

В дальнейшем возможен счётчик:

``` text
🎓 3
```

## 6. Экран «Учёба»

Экран показывает исходный текст, правильный вариант, конкретные правки и
короткие объяснения.

``` text
Исходное:
I don't know what he want от меня

Правильно:
I don't know what he wants from me.

❌ he want
✓ he wants

Present Simple:
для he/she/it используется форма с -s.

от меня → from me
```

Слова, выражения и идиомы можно добавлять в Vocabulary.

## 7. Vocabulary

Если пользователь не знает слово или выражение, он пишет его на родном
языке прямо внутри иностранного предложения.

``` text
I need to договориться with him.
```

AI определяет подходящий перевод по контексту.

Неизвестное слово или выражение сохраняется вместе с контекстом, а не
только как пара слов.

``` text
Source:
договориться

Target:
arrange / agree / come to an agreement

Original context:
I need to договориться with him.

Corrected context:
I need to arrange it with him.
```

Vocabulary --- отдельный учебный модуль. Метод изучения слов будет
спроектирован отдельно.

# Desktop

## 8. Desktop UX

Пользователь пишет непосредственно в активном поле другого приложения.

После написания нажимает глобальную горячую клавишу `Translate`.

``` text
Active Input Field
→ Global Hotkey
→ получение текста
→ JustTalk easy
→ AI
→ Learning Data
→ Translation
→ замена текста в Active Input Field
```

## 9. Desktop MVP

Для первого прототипа допустима clipboard-механика:

``` text
активное поле
→ выделить текст
→ copy
→ получить clipboard
→ AI processing
→ записать результат в clipboard
→ paste
```

Позже использовать системные Accessibility / UI Automation API для более
надёжного взаимодействия.

Нужен fallback для приложений, где автоматическое получение текста
невозможно.

Собственное поле JustTalk easy может существовать как резервный режим,
но не как основной UX.

# Mobile

## 10. Mobile UX

Основной механизм на мобильном устройстве --- собственная системная
клавиатура:

``` text
JustTalk easy Keyboard
```

Пользователь пишет прямо в Telegram, WhatsApp, Gmail, браузере и других
приложениях.

## 11. Панель клавиатуры

Над клавишами располагается панель:

``` text
┌───────────────────────────────────────┐
│ ⇄ Translate        🎓 Учёба       ⚙  │
├───────────────────────────────────────┤
│          обычная клавиатура           │
└───────────────────────────────────────┘
```

Пользователь пишет:

``` text
I don't know what he wants от меня
```

Нажимает `Translate`.

Клавиатура получает доступный текст текущего поля, передаёт его на
обработку и заменяет результатом:

``` text
Я не знаю, чего он от меня хочет.
```

Пользователь нажимает Send.

## 12. Mobile Learning

Если найден учебный материал, кнопка `Учёба` получает визуальный
индикатор.

Нажатие открывает основной интерфейс JustTalk easy с подробным разбором.

## 13. Android

Android --- приоритетная мобильная платформа для первой мобильной
версии.

Основной механизм:

``` text
Custom Keyboard / IME
```

Клавиатура должна: - вводить обычный текст; - получать доступный
контекст вокруг курсора; - иметь кнопку Translate; - заменять текст
после обработки; - передавать учебные события основному приложению; -
открывать экран «Учёба»; - взаимодействовать с Vocabulary.

## 14. iOS

Использовать `Custom Keyboard Extension`.

Нужно отдельно учитывать ограничения iOS на доступ к содержимому
приложений, сетевые запросы клавиатуры, secure text fields и обмен
данными между keyboard extension и основным приложением.

iOS требует отдельного технического проектирования.

# Privacy

## 15. Приватность

Текст не должен отправляться AI автоматически.

Отправка происходит только после явного действия пользователя, например
`Translate`.

Отдельно учитывать: - password fields; - secure input; - банковские
данные; - персональные данные; - приватные сообщения; - локальное
хранение истории; - возможность отключить историю.

В защищённых полях AI-функции должны отключаться.

## 17. Главная продуктовая концепция

JustTalk easy --- не отдельное место, куда пользователь должен приходить
учить язык.

Программа встраивается в реальную коммуникацию и превращает ежедневную
переписку в персональный учебный материал.

> JustTalk easy --- языковой обучающий слой поверх обычной коммуникации
> пользователя.
