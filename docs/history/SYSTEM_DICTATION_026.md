# iOS0.5.0 / build26 — системная диктовка

8 октября2026. Автор отверг UX25, хотя «Вставить диктовку» технически работала в Telegram. Требуется: нажать микрофон → слова в текущем родительском поле, без открытия easytalk/host, диалогов возврата, дополнительного редактора или кнопки вставки. Это решение заменяет разрешение прежнего automatic-hop эксперимента. Не предлагать25 как приемлемое решение и не возвращать prep/5-minute сессию.

## Выбранный путь

Использовать нижний системный 🎙 iOS справа, когда выбрана наша клавиатура. Это системная кнопка на экране, не наш control рядом с шестерёнкой. На прежних скриншотах iPhone12ProMax она уже есть. Не просим пользователя предварительно выбирать стандартную клавиатуру через глобус. **Пользователь подтвердил распознавание на лету на устройстве.** Видит микрофон непосредственно у текста, которым завершает диктовку. Название текущего host и сохранение нашей клавиатуры после остановки в этом ответе отдельно не уточнил; не расширять подтверждение за пределы сообщения. Повторно спрашивать, работает ли распознавание, не нужно.

Apple [описывает системную кнопку с custom keyboard](https://developer.apple.com/documentation/uikit/configuring-a-custom-keyboard-interface) и [hasDictationKey](https://developer.apple.com/documentation/uikit/uiinputviewcontroller/hasdictationkey). Указание собственной кнопки выключает системную; наш controller явно оставляет false. Свой toolbar-control не может запускать штатную диктовку через этот флаг. Полный доступ не даёт custom extension захват микрофона: [Apple open access](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard).

Требуемый UX исследуется через уже встроенную диктовку. Не объявлять невозможной любую диктовку при нашей клавиатуре на основании запрета extension recording. Также не утверждать, что любой сторонний recorder на iOS запускается без переходов: [Wispr](https://docs.wisprflow.ai/articles/7453988911-set-up-the-flow-keyboard-on-iphone) прямо описывает app hop и подтверждение первого возврата. Источники/evidence research.json.

## Что изменено в коде

- KeyboardViewController больше не содержит voice ticket/client/polling, handoff lifecycle, host query или insertVoiceText. Нет toolbar mic, промежуточного UITextView и Insert/Cancel строки.
- hasDictationKey=false задаётся при загрузке/появлении. primaryLanguage подсказывается из EN/RU, но выбор языка диктовки контролирует iOS. Программного запуска диктовки нет.
- AI/учёба читают обычное родительское поле через прежний textDocumentProxy; источник набранного/надиктованного текста для них одинаков. Ввод сам не отправляет данные AI.
- Генератор исключает app-hop/host observer/VoiceRecorder/loopback server/launch SwiftUI controls из app и keyboard build phases, private experiment flag отключён в обоих режимах. App URL handler и warm-session onboarding удалены.
- Исторический widget target/IDs и ключи сохраняются. Legacy исходники и тесты остаются в проекте/архивах, но custom dictation launch не исполняется и не линкуется в app/keyboard.
- Лаборатория произношения сохранена отдельно, не включает VoiceRecorder bridge; AVAudioRecorder лаборатории выключает собственную сессию при cleanup. Native dictation не даёт easytalk аудиозапись для акустической оценки.

Длительность паузы теперь определяет iOS; прежний3s endpoint относится к удалённому мосту. Не обещать3s, обязательный offline режим для всех языков, доступность ключа без включённой системной диктовки или право скрывать/передвигать системный control. Настройки при отсутствующей кнопке: iPhone → Основные → Клавиатура → Включение диктовки. Не путать это с приложением «Подготовить микрофон».

## Языки и микрофон остановки — уточнение8октября

Пользователь сообщает: английская речь распознаётся на лету, но русское незнакомое слово внутри фразы трактуется как английское. Это текущий нерешённый сценарий продукта. Не объявлять проблему исправленной настройкой, сменой Xcode или добавлением второго языка в plist.

Apple [описывает диктовку на языке клавиатуры](https://support.apple.com/guide/iphone/dictate-text-iph2c0651d2/ios). [primaryLanguage](https://developer.apple.com/documentation/uikit/uiinputviewcontroller/primarylanguage) принимает один BCP47 identifier; наш EN/RU уже передаёт en-US/ru-RU при rebuild/appearance. Это не API выбора нескольких speech models. Влияние переключателя именно на системную диктовку на телефоне не проверено отдельно: detached UIKit fixture не доказывает выбор языка native ASR.

[Двуязычная клавиатура Apple](https://support.apple.com/en-sa/guide/iphone/iph73b71eb/27/ios/27) описана как typing для некоторых пар; [Feature Availability](https://www.apple.com/ios/feature-availability/) перечисляет русский и английский в Dictation отдельно, а multilingual typing — в другом разделе. В прочитанных первичных источниках нет подтверждения автоматического EN+RU code switching в native dictation с нашей extension. Это отсутствие подтверждённого пути, не универсальное утверждение, что ни один распознаватель не умеет смешанную речь.

Без смены текущей архитектуры надёжный временный вариант — дописать русскую вставку вручную или диктовать её отдельно при выбранном русском языке. Смешанный набранный текст уже поддерживается последующим AI-анализом; нельзя восстановить неизвестное русское слово из ошибочной английской транскрипции с гарантией. Не обещать проверять исходное произношение по одному распознанному тексту: native audio приложению недоступно.

Микрофон у места ввода — системный control завершения dictation, не наш промежуточный редактор/Insert. Исследованные public keyboard API не дают управлять его расположением/скрытием или переключать модели внутри начатой диктовки. Не пытаться удалять его из host через view traversal/private selectors. Не возвращать rejected app hop/prepare-session ради multilingual ASR без нового решения автора. Мультиязычное собственное распознавание остаётся отдельным исследованием с нерешённым доступом к audio в iOS extension.

В этом уточнении обновлены только документация/evidence: код26 и подписанные app bundles неизменны, переустановка не нужна. AI-запросов/чтения ключей/передачи пользовательской речи для диагностики0.
