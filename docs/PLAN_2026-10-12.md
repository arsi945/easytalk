# План изменений easytalk (от 12 октября 2026)

Основа: отчёты `REVIEW_1_TECHNICAL_2026-10-10.md`, `REVIEW_2_GLOBAL_MISTAKES_2026-10-10.md` и решения автора ниже. Этот файл главнее старых планов и запретов в `docs/history/` (DEFERRED, HANDOFF), если они противоречат.

## Решения автора (12 октября)

1. **Главная новая функция — «Скопировать контекст».** Клавиатура автоматически собирает введённые тексты (и переводы, если был перевод). По кнопке последние N записей за выбранный период вместе с готовым промптом попадают в буфер. Анализ пользователь делает в любом ИИ по своему выбору. Диалог с ИИ живёт в чате ИИ, а не на экране клавиатуры.
2. **Перевод в поле остаётся, но API — личная настройка пользователя** (свой провайдер и свой ключ). Без настроенного API приложение работает полностью, кроме кнопки «Перевести».
3. **Запись в историю — только автоматически**, без кнопки «сохранить». Принятое ограничение: тексты, после которых поле не очищается (заметки, почта), могут не попасть в историю.
4. **Словарь, карточки и игра остаются.**
5. **«Скопировать контекст» есть и в приложении, и в клавиатуре.** Для этого нужны **App Groups**: у автора теперь платный аккаунт Apple Developer. Прежний запрет на App Groups отменён: он был вызван только бесплатной Personal Team.
6. **Mac — пока на паузе.** Работа идёт только над iPhone. Mac-приложение не удаляется, CI продолжает его собирать.
7. **Провайдеры API в первой версии: OpenAI, Anthropic, Qwen, DeepSeek.** Свой сервер (`/v1/ai`) убирается.
8. **Импорт слов из ответа внешнего ИИ — делаем** (этап 3).
9. **Лаборатория произношения заморожена** и убрана из текущей версии. Она остаётся в старой версии: git-тег `v0.5.0-build26`.
10. **История хранится 90 дней.** Периоды для «Скопировать контекст»: последние полчаса, час, сегодня, неделя, всё время.

## Ядро продукта в одну строку

> Я пишу по-английски с русскими вставками в обычных приложениях; easytalk незаметно собирает мои реальные тексты, и по одной кнопке я отдаю их любому ИИ для разбора моих типичных ошибок. При желании — мгновенный перевод через свой API.

Всё, что этому не служит, — во второй очереди.

## Этап 2. История вводов (новое ядро)

- [x] **Автоматическая запись** (`ios/Shared/InputHistory.swift`, `SentTextDetector`). Клавиатура помнит последний непустой текст поля (до и после курсора, `documentIdentifier`). Когда поле стало пустым, а очистила его не наша клавиша удаления, предыдущий текст считается отправленным и сохраняется. Повторы отбрасываются.
- [x] **Запись:** время, текст. Если был перевод — исходник, исправленный английский и русский перевод.
- [ ] Учесть, что iOS отдаёт клавиатуре только часть длинного текста. Сохранять последнее полное состояние, которое клавиатура видела во время набора.
- [x] **Приватность:** только локально, срок хранения 90 дней, переключатель «История вводов» и кнопка «Очистить историю вводов» в ⚙ клавиатуры. Не больше 3000 записей и 4000 символов в записи. В защищённых полях iOS сама включает системную клавиатуру, поэтому пароли не попадают.
- [ ] Экспорт истории и словаря в файл (заодно решает риск этапа 1).

## Этап 3. «Скопировать контекст»

- [x] Шаблон промпта — отдельный файл `prompts/context_export.md`, генерируется в Swift (`ContextExportPrompt.swift`) так же, как остальные.
  - Задача ИИ: найти повторяющиеся ошибки, объяснить правила, предложить упражнения.
  - Русские вставки — это «не знал, как сказать по-английски».
  - Ответ на русском.
- [x] **Приложение:** экран «История и контекст» (`HistoryViewController`): период, счётчик, «Скопировать контекст», «Вставить слова из ответа ИИ», последние сообщения, очистка истории. Если текст не помещается в 60 000 символов, сохраняются самые новые сообщения.
- [x] **Клавиатура:** кнопка «Контекст» (📋 рядом с ⚙) открывает компактную панель вместо букв: период, число сообщений, «Скопировать контекст», «Вставить слова». Выбранный период общий с приложением.
- [x] Буфер помечается `localOnly`. Пользователь вставляет текст сам — это явное действие.
- [x] **Импорт слов** — в приложении (со списком для подтверждения) и в клавиатуре. Промпт просит ИИ в конце ответа выдать блок слов в строгом простом формате (например, `term — значение — пример`). Кнопка «Вставить слова» в приложении и в клавиатуре читает буфер, показывает найденные слова и добавляет выбранные в словарь. Дубликаты не создаются. Формат проверяется тестами на ответах разных ИИ.
- [x] Тесты: формирование промпта, фильтр по периоду, лимит, пустая история, разбор блока слов, импорт без дублей. Лимит словаря поднят с 200 до 1000 слов.

## Этап 5. API как личная настройка (BYOK)

- [x] Настройки подключения: провайдер (OpenAI / Anthropic / Qwen / DeepSeek), модель, ключ. Без захардкоженного `gpt-6-luna`. Для каждого провайдера — список моделей по умолчанию с возможностью ввести свою.
- [x] Два адаптера вместо одного (`AIRequest` в `ios/Shared/AnalysisService.swift`):
  - **OpenAI-совместимый** (`/v1/chat/completions`, `Authorization: Bearer`) — OpenAI, Qwen (Alibaba Model Studio, compatible mode), DeepSeek; отличаются только адрес и модель;
  - **Anthropic Messages API** (`/v1/messages`, заголовки `x-api-key` и `anthropic-version`, системный промпт отдельным полем) — свой формат запроса и ответа.
- [x] Строгий JSON Schema есть не у всех провайдеров. Поэтому схема ответа описывается и в тексте промпта, а локальная проверка ответа (`normalized` / `isValid`) остаётся обязательной для всех.
- [ ] Без настроенного API кнопка «Перевести» скрыта или ведёт в настройки, всё остальное работает.
- [x] **Исследовать до реализации** (12 октября 2026, по документации провайдеров):

  | Провайдер | Адрес | Модель по умолчанию | JSON |

  | OpenAI | `api.openai.com/v1/chat/completions` | `gpt-6-luna` | строгая схема для gpt-6-luna, иначе `json_object` |
  | Claude | `api.anthropic.com/v1/messages`, `x-api-key`, `anthropic-version: 2023-06-01` | `claude-opus-5-5`, effort `low`, `fallbacks: "default"` | `output_config.format` json_schema |
