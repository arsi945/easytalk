# Отчёт 1. Технический разбор easytalk

Дата: 10 октября 2026. Состояние: iOS 0.5.0 / build 26, macOS 0.4.1 / build 11.
Метод: полное чтение исходников (iOS-клавиатура, iOS-приложение, `ios/Shared`, Mac, `EasyTalkCore`, скрипты, промпты). Код ничем не запускался, все выводы получены чтением. Ключевые находки перепроверены по исходникам вручную.

---

## 1. Что это за приложение

Это личный инструмент для русскоязычного автора, который пишет по-английски с русскими вставками.

- **iPhone.** Своя клавиатура (keyboard extension). Пользователь пишет в любом приложении, нажимает «Перевести», и текущий абзац уходит в OpenAI. Ответ — исправленный английский, русский перевод и разбор ошибок. Перевод заменяет текст в поле. Разбор открывается внутри клавиатуры («Учёба»): правки, «В словарь →», карточки, игра. Для голоса используется системная кнопка 🎙 iOS.
- **Mac.** Плавающая панель справа (NSPanel + SwiftUI). Ввод, перевод, разбор, словарь. Выделение принимается через «Службы», есть режим «Перевести и вставить» в чужое приложение через Accessibility и ⌘V.
- **Общее.** Контракт ответа AI, проверка правок, словарь, идиомы, карточки.

## 2. Как устроено

```
                    prompts/*.md ──(ios/generate_project.py)──► AnalysisPrompt.swift
                    glossary/*.json ──(scripts/generate_idioms.py)──► IdiomCatalog.swift

 Sources/EasyTalkCore  (Foundation: контракты, Learning/normalize, DraftScope,
        │               CorrectionMarkup, CursorNavigation, StudyContent, + легаси)
        │
 ios/Shared            (AnalysisService → OpenAI, LearningStore → UserDefaults,
        │               StudyPractice, ConnectionSettings, SpeechPlayer, + легаси voice)
        │
   ┌────┴─────────────────────────────┐
   │                                  │
 iOS (Xcode-проект генерируется      Mac (swiftc напрямую из scripts/build.sh,
 Python-скриптом)                    Package.swift есть, но в сборке не используется)
   ├─ EasyTalkKeyboard               ├─ DesktopModel (ObservableObject)
   │   └─ KeyboardViewController     ├─ DesktopViews (SwiftUI) / DesktopEditor (NSTextView)
   │      (1600 строк, всё в одном)  ├─ DesktopWindowController (NSPanel)
   ├─ EasyTalk (app: ключ, онбординг, ├─ DesktopInsertionTarget + Paster (AX + ⌘V)
   │   лаборатория произношения)     ├─ DesktopQA (тесты внутри приложения)
   └─ EasyTalkVoiceActivity (виджет, └─ легаси: PanelController, Settings, AIClient…
       фактически мёртвый)
```

### 2.1 Основной поток (одинаков на обеих платформах)

1. Берётся выделение или текущий абзац (`KeyboardDraft` / `DraftScope`), лимит 2000 символов.
2. `AnalysisOperation` (`ios/Shared/AnalysisService.swift`) отправляет POST на `api.openai.com/v1/chat/completions`. Модель `gpt-6-luna` со strict JSON Schema. Таймаут 30 с, одна повторная попытка «repair».
3. Ответ проходит `LearningResponse.normalized` / `isValid` (`Sources/EasyTalkCore/Learning.swift`). Смещения пересчитываются по тексту, перекрытия отклоняются, применённые правки обязаны точно восстановить `corrected`.
4. Перед заменой проверяется, что поле не изменилось: снимок `InputSnapshot`, идентификатор документа и счётчик поколения `generation`. Поздний ответ отбрасывается.
5. Текст заменяется. На iOS: курсор ставится в конец абзаца, затем `deleteBackward()` × N и `insertText`. Урок записывается, открывается «Учёба».

### 2.2 Хранение и ключ

- Уроки, словарь (до 200 слов), прогресс и настройки — JSON-блобы в `UserDefaults` каждого процесса. На диске хранится только последний урок.
- Ключ API хранится в Keychain (`ThisDeviceOnly`).
- App Groups не используются, поэтому у приложения и клавиатуры отдельные контейнеры. Ключ передаётся из приложения в клавиатуру через **общий буфер обмена** (`easytalk-config:{json}`, `.localOnly`, срок 120 с). Получаются две независимые копии ключа и две несвязанные базы данных.
- Mac хранит всё отдельно, синхронизации нет.

### 2.3 Сборка и тесты

- iOS: `ios/generate_project.py` генерирует `project.pbxproj`, Info.plist и Swift-файлы промптов.
- Mac: `scripts/build.sh` вызывает `swiftc` напрямую с VFS-оверлеем (обход сломанных Command Line Tools), вручную собирает `.app` и подписывает ad-hoc.
- Тесты — собственная обвязка `check(bool, msg)` без XCTest:
  - `ios/Tests/*` (~160 проверок) собирается `scripts/test_ios_core.sh`;
  - `DesktopQA` (~74–90 проверок) вшит в релизный Mac-бинарник;
  - `EasyTalkSelfTest` проверяет только легаси.
- CI нет.

### 2.4 Цифры

| Показатель | Значение |
|---|---|
| Свой код (Swift/ObjC/Python/sh) | ~530 КБ, ~7 тыс. строк, но строки очень длинные (до 530–760 символов) |
| Документация Markdown | ~540 КБ в 42 файлах, **больше, чем кода** |
| `KeyboardViewController.swift` | 1600 строк, 130 КБ, 122 функции, ~60 свойств, из них 19 булевых флагов режима |
| Тестовый код внутри продакшен-класса клавиатуры | ~470 строк (≈30% файла), 140 `precondition` |
| `Vendor/onnxruntime` | 109 МБ ради отложенной лаборатории без весов модели |
| Git | **отсутствует** |

## 3. Что сделано хорошо

1. **Защита от гонок и порчи чужого текста.** Это самая сильная часть проекта. Счётчики поколений, сравнение снимков поля до и после, проверка идентификатора документа, отказ от замены при любом изменении. Ответ AI никогда не применяется «вслепую». То же на Mac: `DraftScope.replacing`, повторная проверка PID, фокуса, диапазона и хэша поля перед ⌘V.
2. **Недоверие к ответу модели.** Смещения не берутся на веру, а пересчитываются. Перекрывающиеся и противоречивые правки отклоняются, результат обязан точно собраться в `corrected`. Ошибка или таймаут сохраняют исходный текст.
3. **Корректная работа с единицами текста** в Core: Unicode scalar для AI, UTF-16 для NSTextView, тесты с эмодзи и суррогатными парами (`Session.utf16Range`, `CursorNavigation`).
4. **Аккуратность к приватности.** Отправка только по нажатию, только абзац, лимит 2000. Ephemeral URLSession, жёсткая проверка хоста OpenAI, запрет URL с credentials. Mac отказывается работать с secure-полями и читает только переданный ему pasteboard Services.
5. **Обход реального краша.** Мост на Objective-C для nullable `documentIdentifier` (`ios/Shared/DocumentProxyBridge.m`).
6. **Внимание к ощущению клавиатуры.** Тапы в промежутки между клавишами попадают в ближайшую, пробел работает как трекпад с осями и порогами, ъ — удержанием ь, второй палец блокируется, раскладка не перестраивается во время drag.
7. **Доступность выше среднего.** Трейты `.keyboardKey`, подписи, custom actions, Reduce Motion, 44 pt, проверка контраста.
8. **Внедрение зависимостей на Mac.** `DesktopAnalyzer`, `MacCredentialVault` и `UserDefaults` подменяются, поэтому `DesktopModel` тестируется без сети и ключа.
9. **Промпт.** Вход оформлен как данные (защита от prompt injection), минимальные правки с контрпримерами, аккуратные правила рода, отдельный режим `revise_analysis`.
10. **Единые источники** промпта и идиом с генерацией Swift. Модель ONNX проверяется по SHA-256 и держится вне extension.

## 4. Что плохо

Уровни: 🔴 исправлять первым · 🟠 важно · 🟡 качество / техдолг.

### 4.1 Ошибки и риски потери данных

- 🔴 **Несогласованные единицы смещения курсора при замене текста.** В `ios/Keyboard/KeyboardViewController.swift:1070` в `adjustTextPosition(byCharacterOffset:)` передаётся `trailingCount`, то есть число графем (`String.count`, `Sources/EasyTalkCore/Learning.swift:215`). Тот же файл в строках 362 и 373 передаёт в этот API UTF-16. Если после курсора в абзаце есть эмодзи или составной символ, курсор не дойдёт до конца абзаца, а следующий цикл `deleteBackward()` удалит не тот текст. Найдено чтением кода, на устройстве не воспроизводилось.
- 🔴 **Удаление не проверяется.** Цикл `deleteBackward()` предполагает, что хост удаляет ровно одну графему за вызов. Результат после вставки не сверяется. Кроме того, iOS отдаёт клавиатуре только часть длинного абзаца: перевод заменит видимую часть, остальное останется. В коде это не детектируется.
- 🔴 **Тихая потеря словаря.** `LearningStore` (`ios/Shared/LearningStore.swift:49–53`) при ошибке декодирования подставляет `?? []`, и следующий `persist()` перезапишет данные пустыми. Добавление любого обязательного поля в `Lesson` или `VocabularyEntry` сотрёт словарь пользователя. `defaults.set(try? encode…)` (строки 52 и 108) при ошибке пишет `nil`.
- 🟠 **Mac: вставка в чужое приложение на фиксированных задержках** (0,25 с до вставки, 0,4 с до восстановления буфера, `Paster.swift:31`). Медленные приложения (Electron, удалённый рабочий стол) могут вставить старое содержимое буфера. AX-вызовы синхронные на главном потоке без `AXUIElementSetMessagingTimeout`, поэтому зависшее чужое приложение подвесит UI. Временное содержимое буфера не помечено как transient, и менеджеры буфера его записывают. Живой проверки этого пути, по собственным документам проекта, ещё не было.
- 🟡 Force unwrap `game!` в клавиатуре. Версия в UI Mac — «0.3.3» (`DesktopViews.swift:412`), в Info.plist — 0.4.1.

### 4.2 Безопасность

- 🔴 **Ключ API лежит в общем буфере обмена до 120 с.** `.localOnly` блокирует только Universal Clipboard. Любое приложение на переднем плане, менеджер буфера или другая клавиатура с Full Access могут его прочитать.
- 🔴 **Импорт настроек из буфера не аутентифицирован** (`KeyboardViewController.swift:1092`). Любая страница или приложение может положить в буфер `easytalk-config:{"mode":"server","endpoint":"https://чужой-сервер/…"}`. После нажатия «Подключить из буфера» все фразы пользователя пойдут на чужой сервер. Минимум: показать хост и спросить подтверждение, либо требовать одноразовый код из приложения. Правильнее: общий keychain access group вместо буфера, если подпись это позволяет.
- 🟠 **Личный ключ OpenAI в клиенте.** Для личного использования это осознанное и допустимое решение. Для любого распространения (TestFlight, друзья, App Store) оно не годится: нужен свой сервер-прокси. Код сервера в проекте когда-то был, но в этот комплект не входит.
- 🟠 **Mac:** настоящий ключ предзаполняется в поле настроек с кнопкой «показать». В режиме `--snapshot` легаси Settings по умолчанию смотрит на `http://127.0.0.1:8787` (`Sources/EasyTalk/Settings.swift:10`), и ради него включён `NSAllowsLocalNetworking`.
- 🟡 В Info.plist iOS-приложения остались `UIBackgroundModes: audio`, `NSSupportsLiveActivities`, URL-схема без обработчика и описания микрофона под удалённую функцию (`ios/generate_project.py:188`). При публикации в App Store это причина для отказа.

### 4.3 Архитектура

- 🔴 **`KeyboardViewController` — god object.** Один класс отвечает за раскладку и ввод, трекпад, настройки, импорт ключа, оба AI-потока, отрисовку урока, словарь, игру, награды, TTS, расчёт высоты и ~470 строк симуляторных регрессий. Режим задан 19 булевыми флагами, ничто не запрещает невозможные комбинации. `render()` при открытой «Учёбе» полностью пересоздаёт дерево view, а таймер прогресса делает это каждую секунду. Этот же файл компилируется ещё и в target приложения.
- 🟠 **Core — не чистый доменный слой.** Рядом с настоящей логикой лежат мёртвый контракт первой версии (`CorrectRequest`, `CorrectionSession`, `AIClient`, `EventLog`), iOS-only типы (`InputSnapshot`, `VoiceDelivery`) и сгенерированные данные. При этом сеть и хранение (`AnalysisService`, `LearningStore`) живут в `ios/Shared` с захардкоженной моделью и русскими строками UI.
- 🟠 **Код между платформами разделяется перечислением файлов**, а не подключением пакета. Списки продублированы трижды (`Package.swift`, `scripts/build.sh`, `scripts/test_ios_core.sh`) плюс `generate_project.py`. Отсюда `#if canImport(EasyTalkCore)` и неизбежный рассинхрон.
- 🟠 **Хранилище — JSON-блоб в UserDefaults** без версии схемы и миграций, каждое изменение перезаписывает всё. Для 200 слов работает, но нет ни экспорта, ни бэкапа, ни синхронизации.
- 🟡 Модель `gpt-6-luna` захардкожена минимум в пяти местах. Для других моделей включается более слабый режим `json_object`.

### 4.4 Мёртвый и легаси-код в поставляемых бинарниках

- iOS: виджет `EasyTalkVoiceActivity` собирается и встраивается, хотя Live Activity никто не запускает. `VoiceBridgeClient` (loopback TCP на порт 49723) компилируется в приложение, а сервера уже нет. `VoiceReturnBridging.h` по факту только импортирует `DocumentProxyBridge.h`. На главном экране остаётся вход в лабораторию произношения, у которой нет модели.
- `generate_project.py` **молча пропускает несуществующие файлы** (строки 158–166). Ссылки на удалённые voice-файлы исчезают тихо, и так же тихо исчезнет файл с опечаткой в пути.
- Клавиатура: 5 `@objc`-обработчиков ни к чему не подключены (`restoreSkipped`, `toggleSuggestionExample`, `toggleWordExample`, `reviewWord`, `startReviewGame`), ещё несколько методов вызываются только из тестов.
- Mac: `PanelController` (~350 строк), `Settings`, `InputTextView`, `Theme`, `AIClient`, `CorrectionSession`, `EventLog` нужны только для скрытого `--snapshot`. `VoiceDelivery` мёртв на обеих платформах. `DesktopQA` с PNG-рендером тоже едет в релиз.
- Неиспользуемые промпты `prompts/correct.md` и `prompts/translate.md`.
- 109 МБ ONNX Runtime ради отложенной функции.

### 4.5 Конкурентность

Swift 5 mode, ни `@MainActor`, ни `Sendable`. Безопасность главного потока держится на комментариях и `precondition(Thread.isMainThread)`. GCD, `Timer` и async перемешаны. Сайд-эффекты в `didSet` (`page` отменяет работу, `compact` двигает окно и пишет defaults). Обновление UI через ручной счётчик `revision`. Переход на Swift 6 будет болезненным.

### 4.6 Сборка, тесты, подпись

- 🔴 **Нет git** и вообще никакого контроля версий. История — tar-архивы, и в переносной комплект они не входят.
- 🟠 Тесты не XCTest и не запускаются из Xcode. Регрессии UIKit — `precondition` внутри продакшен-классов. Тесты Mac вшиты в приложение, зависят от порядка и не изолированы. AX, ⌘V и восстановление буфера не тестируются вообще. Покрытие не измеряется.
- 🟠 Mac-сборка — ручной `swiftc` без инкрементальности, только под архитектуру текущей машины. Подпись ad-hoc без hardened runtime и нотаризации, поэтому разрешение Accessibility слетает после каждой пересборки. В `runtime.json` бандла зашиваются абсолютные пути машины разработчика (`scripts/build.sh:38`).
- 🟡 iOS-проект генерируется самописным Python вместо XcodeGen, Tuist или локального SPM-пакета.

### 4.7 Читаемость кода

Код очень плотный: по нескольку операторов через `;`, объявления в одну строку, строки до 530–760 символов. В клавиатуре 109 строк длиннее 160 символов, в `DesktopViews` — 70. Русские строки UI захардкожены без локализации. Данные модели хранятся в `accessibilityIdentifier` / `accessibilityValue`, из-за чего VoiceOver местами читает фразу дважды. Такой код тяжело ревьюить, диффы нечитаемы, а у ИИ-агентов выше шанс ошибиться при правке.

### 4.8 Качество клавиатуры как клавиатуры

Нет автокоррекции, подсказок и `UITextChecker`. Нет автозаглавной в начале предложения, caps lock, точки по двойному пробелу. **Нет буквы ё.** Нет звука клика и хаптики. `returnKeyType` и `keyboardType` игнорируются, так что email, URL и числа получают одну раскладку. Ввод срабатывает на touch-down. Нет ландшафта и Dynamic Type. Выбор EN/RU не сохраняется. Для ежедневной клавиатуры это главный риск: пользователь будет переключаться обратно на системную, и вместе с ней уйдёт весь продукт.

### 4.9 AI и промпт

- Один монолитный промпт (~5,8 КБ) за каждый запрос делает исправление, смещения, перевод, объяснения до 600 символов и до 6 словарных статей. Ответ длинный (лимит 6000 токенов), это дорого и медленно. Repair-повтор удваивает стоимость.
- Модель просят считать смещения в code points, хотя клиент всё равно пересчитывает их сам. Это лишняя работа модели и основной источник repair-ошибок.
- В примере схемы лишняя скобка (`prompts/analyze_translate.md:30`), а для моделей без strict schema это важно.
- `context` всегда `casual_chat`, и промпт не говорит, что с ним делать.
- **Качество ответов модели не измеряется.** Golden-набор существовал только для старой операции `correct` и был заброшен.

## 5. Технические приоритеты (предложение)

1. **Гигиена (день работы).** `git init` и первый коммит текущего состояния. Удалить мёртвый код: виджет, voice bridge, легаси Mac-панель, `VoiceDelivery`, старые контракты, лишние ключи Info.plist. Генератор должен падать на отсутствующем файле.
2. **Безопасность и данные.** Убрать передачу ключа через буфер или хотя бы подтверждать хост при импорте. Версионировать хранилище, при ошибке декодирования не перезаписывать данные, а сохранять бэкап. Добавить экспорт словаря.
3. **Исправить замену текста на iOS.** Единые единицы UTF-16, проверка результата после удаления и вставки, детектирование усечённого контекста.
4. **Сделать Core одним SPM-пакетом**, от которого зависят обе платформы. Перенести тесты в XCTest и запускать их в Xcode, затем в CI.
5. **Разрезать `KeyboardViewController`:** раскладка, сервис замены текста, AI-координатор, дочерние контроллеры Study / Dictionary / Game, `enum Mode` вместо флагов.
6. **Клавиатура как клавиатура.** Буква ё, автозаглавная, `UITextChecker` или подсказки, звук и хаптика, учёт `keyboardType`.
7. **Измерять качество AI:** маленький golden-набор реальных фраз автора с разрешения и регулярный прогон при каждом изменении промпта. Облегчить промпт: убрать смещения, словарные статьи запрашивать лениво.
